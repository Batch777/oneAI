# oneAI 邮件分流与多端详情页 Spec

状态：供用户 Review；2026-09-22。本文区分已实现与后续项。目标是减少待核对列表中的噪声，同时保留验证码和账户验证提示。

## 1. 用户流程

收到邮件 → 持久化原件与版本事件 → 分类 → 普通任务 / 已筛选邮件。

最近 15 分钟收到的验证码、账户验证邮件另显示应用内提示：发件人、主题、验证码、候选链接域名。提示最多五条；验证码和链接从原文确定性提取，不由模型编造。旧邮件导入不能触发新邮件提示。收起提示只影响当前页面，刷新后仍可能重现。

用户进入“已筛选邮件”可查看原始内容、分类理由及评分，也可以“恢复到任务列表”。恢复决定优先于后续自动分类；不删除 Outlook 邮件，不标为已读，不自动打开链接、激活账户、回复或发送。

## 2. 类别与置信度

| 类别 | 显示名称 | 默认处理 |
| --- | --- | --- |
| verification | 验证码 / 账户验证 | 高置信度分流，新近来信另行提示 |
| promotion | 推广广告 | 高置信度分流 |
| action | 需要处理 | 保留任务 |
| notification | 普通通知 | 保留任务 |
| uncertain | 待判断 | 保留人工核对 |

每条记录保存 category、confidence、reason、source、version、filtered，关联稳定 task_id。source 明确显示规则、AI、回退或用户决定。模型分数不是校准后的正确率；规则的 0.99 也是策略分值。不能宣称“99% 准确”。

自动分流仅允许 verification / promotion，阈值 0.98。重要事项保护优先：异常登录、安全警报、账单、付款、面试、截止等信号直接保留。该词表是保守起点，不能覆盖所有重要邮件。

规则首版：验证码用途词加 4–8 位短数字；广告标题加正文退订标记；账户验证用途加 HTTPS 候选链接。只出现六位数字、退订按钮或普通“确认”不够。人工修改、已核对或已归档任务不做历史自动隐藏。

## 3. AI 调用和成本边界

已实现可替换模型接口与 OpenAI-compatible / DeepSeek 分类入口，要求结构化 JSON；无工具权限。只提供主题和最多约 5000 字符正文摘录，4–8 位数字预先隐藏；姓名、地址等自由文本并未完整脱敏。模型无效输出、超时或异常回退到待判断。单请求超时 20 秒，不自动重试。

当前常驻 worker 使用本地规则，不会因为历史邮箱有数千封邮件就自动批量调用收费模型。AI 通过 `python -m oneai.mailtriage --ai --limit 20` 做预览；`--apply` 才持久化该批决定，每批最多 100 封。使用现有模型配置，未配置密钥时明确失败，不冒充 AI 分类。真实 AI 分类质量尚待用户标注样本评估。

待 Review 决策：选择模型与允许传出的邮件范围；确认日调用/费用上限后再接入持续 AI 分类队列。建议先标注 100–200 封，包括混合目的邮件、重要安全邮件和广告，分别统计误隐藏率、漏过滤率与置信度可靠性，再调整阈值。用户纠正目前按单封持久化，尚不自动推广成全局发件人规则。

## 4. 验证信息提取

验证码支持验证码 / 动态口令 / verification code 等上下文与 4–8 位数字，保留前导零。识别失败时不猜测，不把普通房间号、订单号直接当验证码。未来可扩展有上下文的字母数字码。

账户验证只展示 HTTPS 链接，拒绝凭据嵌入、IP 地址、localhost / local / internal 及非标准端口，最多三个。链接仍可能是追踪或非验证用途，UI 显示目标域名并要求用户核对；HTTPS 和发件人字段不证明可信。链接可能包含一次性凭证，不写入日志、Git、分类原因或通知标题。点击前确认域名，在系统浏览器打开；不自动访问，也不预取链接。

应用内提示要求客户端在线并打开。另新增 Web Push 通道，详见下节。15 分钟是提示窗口，不代表服务商的验证码有效期。

## 5. 多端排版契约

相同内容、任务 ID 和草稿版本跨端一致；布局按屏幕宽度变化。手机使用列表与详情切换，桌面使用双栏。进入详情后不允许横向溢出、标题挤走关闭按钮、文本被固定高度截断。原文弹窗内部滚动，关闭后回到检索结果。

搜索结果正文按卡片宽度重排。原始来源保留提取文本行序以核对引用；长 URL / 文件路径允许断行。手机输入框字体至少 16px，避免 iOS 聚焦自动放大导致视觉布局跳动。触发外链必须是用户实际点击，不能由页面脚本导航绕过工作空间限制。

配对码：四个大输入格，同时支持逐位键入、整码粘贴、系统 OTP 填充、前导零、退格和方向键修改。底层合并成一个四位码提交；不自动提交，保留连接按钮。生成的配对码也显示为四格。四位码安全策略沿用既有确认：十分钟、仅一次、只有一个有效码，单 IP 失败五次、全站失败十次的十分钟窗口。

## 6. 验收矩阵

宽度至少覆盖 390px 手机、768px 平板、1280px 桌面。必须实际点击进入：任务 / 邮件详情、历史来源弹窗、草稿编辑、设备配对、四格登录。分别检查长中文、英文、URL、引用路径和空状态，文档 scrollWidth 不得超过可视宽度。

功能检查：重要事项不被广告分类隐藏；人工恢复在重跑后保持；旧验证码不弹新提示；前导零正确；危险 URL 被拒绝；未登录不能读取验证信息；模型输出注入或 JSON 错误不能执行操作；未配置 AI 时明确标注规则。

发布：先运行核心测试，再部署备份，验证 worker / Web / Outlook 定时器健康。原件和已登录设备保留。首次历史规则分流每轮最多 100 封，属于可逆分类变更，可从“已筛选邮件”恢复。

## 7. 折叠详情与按需回复（2026-09-22）

原始内容、检索材料、用户身份、User scope、规则与原文依据默认折叠，独立展开。待处理和已筛选邮件也必须有折叠原文。当前身份和规则明确标为当前资料，不伪装成生成时的历史快照；引用原文仍按内容版本定位。

回复模板不随后台处理自动生成。点击“生成回复模板”并确认后生成待编辑模板，版本递增、原核对失效；取消不产生写入。稳定指令 ID 防止重试重复生成，第二设备旧版本返回冲突。同一任务只生成一次，之后通过编辑修改。当前模板是确定性占位文本，不冒充模型撰写，也不授权发送。

## 8. 锁屏推送

选择标准 Web Push：HTTPS 页面 → 用户点击授权 → Service Worker 订阅 → 云端持久化 outbox → 推送服务 → 设备通知。云端每 30 秒运行独立定时任务，不依赖 Mac 或打开的对话窗口。

iPhone 需从 Safari 添加到主屏幕后授权；这条 Web Push 路径不要求付费 Apple 开发者计划。[Apple 官方说明](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers)、[WebKit iOS 主屏幕要求](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)。原生 WKWebView 客户端的 APNs 尚未配置，不能把原生构建成功当成锁屏验收成功。

锁屏仅显示通用“收到验证邮件”，不携带主题、发件人、验证码或验证链接。解锁进入已登录工作空间后查看原文提取结果。订阅只接受 Apple/Google/Mozilla 已知 HTTPS 推送域，拒绝重定向、非标准端口和无效密钥。私钥留在云端受限文件，不进入 Git。

只通知订阅后新到且 15 分钟内的邮件，不重放历史导入。每设备、每邮件持久化去重；临时失败最多五次，过期停止，404/410 删除失效订阅。登出、断开设备或会话过期阻止后续发送。已经交给服务商的通知无法撤回；崩溃恢复可能重新投递，由通知 tag 合并，不能声称严格恰好一次。

“发送测试通知”每设备一分钟一次，状态区分等待、失败、过期、服务商已接收。服务商接收不代表锁屏显示；用户系统通知权限、专注模式和实际设备还需验收。

## 10. 任务延迟、三级详情与 Jev（本轮修订）

**本节取代此前多个独立折叠区的布局。**

一级直接显示事项、待确认内容和回复草稿，提供“生成回复模板”“补充信息 / 编辑草稿”“确认草稿内容”“归档事项”等显式操作。已筛选邮件提供“恢复为待处理事项”。没有接通的发送或提交能力不显示为可执行按钮。

二级只有一个“原文与检索依据”入口，展开后直接显示原文、检索片段和引用按钮；不要求逐段再展开。三级只有一个“身份、范围与分类规则”入口，一次展示当前身份、scope、规则与分类理由。第三级第一次展开才请求 `/api/tasks/{task_id}/context`，失败可单独重试。

### 延迟问题与修复

- 原任务详情每次调用 `load_context`，遍历全部 Markdown 后才筛选 rules。现在只遍历 rules 目录；详情首屏不再读取 context。
- 浏览任务使用 SQLite 只读连接，不在每个 GET 中运行建表语句或文件权限更新；任务列表增加排序索引。
- 指令数据库操作移入线程池，避免数据库等待堵住 Web 请求事件循环。
- 点击后立即切换至带任务标题的加载状态，12 秒超时提供重试/返回。快速切换取消前次请求；序号校验阻止迟到响应覆盖新任务。轮询响应也检查选择序号和编辑状态。
- 本地合成 7,000 文件基准：旧目录扫描约 406.37ms，限定规则目录约 0.36ms。仅表示该步骤耗时，不代表公网端到端性能。可用 `PYTHONPATH=. python scripts/benchmark-context.py` 重现。

### 日志契约

核心 API 输出结构化 `api_request`：随机 request_id、路由模板、HTTP 方法、状态和 duration_ms；响应附带 X-Request-ID 与 Server-Timing。未知路由统一 unmatched，不记录实际 URL、查询参数、任务 ID、cookie、请求体、邮件或验证码。关闭 Uvicorn 原始访问日志，避免检索查询出现在新增应用日志中；网关原有日志策略另行管理。未处理异常返回通用错误及请求编号，不输出异常消息里的用户数据。当前日志用于耗时和失败定位，不代替已有任务变更历史。

### Jev 接入决策（历史方案）

**此小节已由 [Jev 分类 v2 spec](JEV-MAIL-CLASSIFICATION-SPEC.md) 取代。现已上线独立 Jev 分类服务，完成开户、密钥配置、五封合成样本及三封实际邮件的真实调用，详见 v2 spec。**

官网已核验为 TypeSafe AI，注册入口为 https://console.typesafe.ai/ 。已使用关联 Outlook 请求验证码，oneAI 云端实际收取验证邮件并成功完成邮箱验证。后续页面新增主客户协议与数据处理附录，等待用户对新增协议确认；尚未完成开户、未购买额度、未启用真实邮件的 Jev 分类。

官方 API：`POST https://api.typesafe.ai/v1/systemone`。实现可选 `--provider jev`，固定模型 `jev-1.13.0`；调用一次同时询问类别 Choice 和需人工关注 Noul，10 秒超时，无自动重试、禁止重定向。[官方快速开始](https://docs.typesafe.ai/introduction/quickstart)、[问题类型](https://docs.typesafe.ai/primitives)。

先保留重要事项保护、规则提取验证码和人工恢复优先。Jev 只替换不足以判断时的模型分类分支；不承担验证码生成、点击验证或执行邮件指令。只提交有界摘录，短数字和 URL 已隐藏，但自然语言中的私人信息并未完全匿名化。

Jev confidence 是从概率分布计算的统计量，不能直接当成邮箱准确率。[官方置信度说明](https://docs.typesafe.ai/confidence)。自动隐藏的策略分数取分类 confidence、选中类别 probability，以及 1−需人工关注概率三者最小值；仍要求 ≥0.98。格式异常、限流和网络失败保留核对。当前是可运行适配器与模拟响应测试，未完成真实样本效果评估，也未启用常驻 Jev 分类。

## 11. 增量内容哈希索引（2026-09-22）

目标是减少重复扫描资料正文的成本，保留已有 SHA-256 原文版本和可回溯引用。此次覆盖 Markdown 知识库及已解析的论文文本；不改变 PDF 解析器，也不新增语义向量检索。

- SQLite `file_state` 保存相对路径、文件大小、纳秒级修改/变更时间、设备与 inode、上次内容校验时间。元信息未变且距上次校验不足 24 小时，跳过正文读取、分块和写索引。
- 新增、修改或校验到期的文件才读正文、计算 SHA-256。内容哈希相同只更新校验状态；不同才替换分块并保留版本快照。强制重建跳过缓存，分块规则升级后应强制重建。
- 遍历前剪除生成的任务、草稿、指令目录，避免几千个派生文件拖慢资料检索。目录链接不递归，文件链接保持现有资料库边界检查。
- 删除、改名移除当前搜索结果，历史引用仍可读取。读取前后核对文件指纹；变化时重试一次，仍不稳定则整次索引事务回滚。不可访问的目录不能误判为批量删除。
- 旧索引首次运行自动补齐缓存。缓存属于派生状态，可重新生成；原始 Markdown 与历史证据不依赖它存活。
- Worker 将 `checked/hashed/skipped/removed/chunks_written/duration_ms` 写入 `state/index-status.json`，不记录资料内容。

边界：普通扫描仍是 O(文件数) 的元信息检查，不是文件系统事件驱动。每日内容校验和首次建索引仍需读全部正文；iCloud 未下载文件仍可能受下载速度影响。此轮不承诺 PDF 解析与向量嵌入的耗时收益。

合成基准：1,000 份约 4KB 资料、7,000 个排除任务，首次约 1,004ms；无变化约 18ms（0 次内容哈希）；单文件修改约 26ms（1 次内容哈希）。结果为开发机测量，非公网 SLA。用 `PYTHONPATH=. python scripts/benchmark-index.py` 重现。

新增 9 项索引回归覆盖跳过未变正文、同大小且恢复修改时间的编辑、仅触碰元信息、改名/删除/历史引用、到期校验、旧库迁移、派生目录剪枝、读取中修改回滚和目录不可访问回滚。

### 真实验证码流程发现的问题

TypeSafe 验证邮件将六位验证码单独放在正文一行，原有相邻关键词表达式没有提取成功。新增保守规则：必须出现“使用下方验证码”等明确提示，且全文只有一个独占一行的 4–8 位数字，才将其提取为验证码；保留前导零，多候选不猜测。测试使用虚构数字，不保存真实验证码。真实邮件已通过 oneAI 收到并用于成功验证；修复后的快捷提取需在云端新版验证，不能用成功阅读原文代替快捷提取验收。
