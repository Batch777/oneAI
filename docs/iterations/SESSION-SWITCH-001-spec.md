## 最小修复步骤

1. 实现会话先读取 `AGENTS.md`、本合同、`docs/ARCHITECTURE.md`、`docs/SELF-DEVELOPMENT.md`、`docs/templates/CHANGE-REVIEW.md`，按需查看 `docs/SESSION-OPERATIONS.md`。读取表中相关源码和测试；`session-controls.js` 仅用于了解控件调用边界。不要复制整段监工历史。
2. 核对分支、HEAD、工作区和本合同。若 HEAD 已变化，记录差异并核对是否仍可按本合同执行；不得悄悄改写 `base_sha`，不得覆盖其他未提交内容。一个 worktree 只允许一个实现者写入。
3. 将会话列表渲染提取为小函数，按稳定会话 ID 查找并复用按钮。新增/删除仅影响相应节点；只有服务端顺序变化时才移动必要节点。标题、运行时、主机名、在线状态及会话状态有变化时原位更新文字，保留按钮及可复用子节点；不要把 metrics/revision 的变化当作整行重建理由。使用 DOM 文本 API，不插入来自服务端的 HTML。
4. 相同成员、顺序和展示数据的连续轮询不得删除、重新插入或替换现有行，也不要重复写入未变文字。保持焦点和列表 scrollTop；无关状态更新不得强制滚至顶部或选中项。按 ID 绑定点击，避免捕获已失效的行索引。
5. 点击已有会话时同步更新所有行的 `.selected` 与可访问选中属性（普通按钮可用 `aria-pressed`），再等待异步事件；始终至多一项选中。详情身份、操作权限和对应草稿立即一致。重复点击当前有效会话应为幂等选择，不清空其内容、游标或草稿；首次恢复持久化 ID 仍须正常渲染。
6. 保留 ID + 单调递增请求序号的事件检查，不能只比较 ID，否则 A → B → A 的旧 A 会误通过。过期成功和失败都不得改写当前内容、cursor 或错误提示。当前请求失败应仍显示错误；清除已消失的选中会话时使旧请求失效，并清理 has-session、选中样式、标题/状态、内容和操作状态。无选中态的整理应兼容现有移除动作后调用 `loadSessions` 的路径，不改写范围外文件。
7. 手机采用一个明确方案：在详情标题区域增加原生 `type="button"` 的“切换会话”入口，连接 `aria-controls="session-list"` 与 `aria-expanded`。取消 has-session 的 82px 覆盖，收起时列表保持可滚动的合理高度（可沿用 160px）；展开时取消该限高，通过页面滚动访问所有会话。显式点击入口可将列表带入视野并合理移动焦点；轮询不得自动收起、抢焦点或重置滚动。选中另一会话后可收起并将详情带回视野，但同一选中项及后台刷新不能反复触发。桌面保持现有列表与详情并排，不引入新导航框架。入口点击只改本地 UI，不发送会话命令。
8. 会话为空、选中会话消失、从 localStorage 恢复、长标题、列表增加/删除/重排、主机离线、observe 会话均需检查。新建返回 ID 暂未出现在列表的现有流程必须在下一次刷新后可正常选中，不因幂等选择优化而永远跳过渲染。
9. 补回归测试并运行下表检查。静态资源最终变化后递增一次 shell 缓存版本；不改其网络、通知或自动重载策略。以实际结果更新本文件“实现与审计回交”部分，形成小步、可审阅 Git 提交。

| 项目 | 必须证明的行为 |
|---|---|

| 保持选中态 | 刷新未结束时通过真实按钮 handler 点击 B，不 resolve 网络即断言仅 B 高亮、selected/持久化 ID/标题/状态/草稿一致；刷新结束后仍一致。无关 metrics/revision 更新不会重建按钮。重复点击 B 不清内容或草稿 |
| A → B → A | A、B 有不同草稿、内容和权限；通过按钮完成往返，每一步即时身份一致，最终回到 A 的草稿和权限；轮询期间同样成立 |
| 乱序请求 | 保留原 A → B 用例；增加旧 A1 → B → 新 A2，先完成 A2，再完成 B 和 A1，内容和 cursor 只属于 A2；同 ID 两个并发 render 最新请求先返回，较旧响应不得追加/倒退 cursor |
| 失败与清空 | 旧会话请求在切换后失败，不覆盖当前提示；当前事件请求失败仍可见。选中项被刷新移除后旧请求完成也不回填；空列表无 selected/has-session 和可操作的残留详情 |
| 移动入口逻辑 | 切换入口始终可用、aria 属性与展开状态一致、轮询保持用户展开状态；点击已有列表行不创建/发送/停止/关闭会话。加载持久化 ID、新建 ID 延迟出现均能正常渲染 |

| 真实点击跨刷新 | 浏览器中在 B 上按下，触发一次列表刷新后在同处释放，B 仍被选中；保留按钮引用验证相同节点仍连接。不能用 stale locator 自动重试掩盖节点替换 |
